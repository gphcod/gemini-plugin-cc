# Contributing to gemini-plugin-cc

Thank you for your interest in contributing! This guide covers the process for reporting issues, suggesting features, and submitting pull requests.

## Getting Started

### Prerequisites

- Node.js 22 or later
- For live testing only: the Antigravity CLI (`agy`), signed in by running `agy` once in a terminal

### Dev Setup

```bash
git clone https://github.com/m-ghalib/gemini-plugin-cc.git
cd gemini-plugin-cc
npm test
```

### Running Tests

```bash
npm test                              # offline suite, runs against tests/fixtures/fake-agy.mjs
node --test tests/runtime.test.mjs    # single file
npm run test:live                     # live agy contract checks (small paid calls)
npm run measure                       # per-call overhead in bytes
npm run generate-commands             # regenerate plugins/gemini/commands/*.md
```

Tests use Node's built-in test runner. No external test framework or dependency is required. See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) for the budgets `npm test` enforces and the agy contract.

### Project Structure

```
plugins/gemini/
  commands/         # Slash commands, generated by scripts/generate-commands.mjs
  hooks/            # Optional Stop review gate
  prompts/          # Review and stop-gate prompt templates
  scripts/          # Companion CLI and the stop-gate hook
  scripts/lib/      # agy runner, state, git, job control, rendering
  schemas/          # Review output schema (passed to agy --json-schema)
  skills/gemini/    # The one model-visible skill, plus prompting references
scripts/            # Command generator, version bump, overhead measurement
tests/              # Test suite; tests/fixtures/fake-agy.mjs stands in for agy
.github/workflows/  # CI configuration
```

## Reporting Issues

- Use the [bug report template](https://github.com/m-ghalib/gemini-plugin-cc/issues/new?template=bug_report.yml) for bugs
- Use the [feature request template](https://github.com/m-ghalib/gemini-plugin-cc/issues/new?template=feature_request.yml) for ideas
- Check existing issues before opening a duplicate
- Include your Antigravity CLI version (`agy --version`) and Node.js version

## Pull Requests

### Before You Start

- Open an issue first for non-trivial changes to discuss the approach
- For small fixes (typos, doc corrections), a PR without an issue is fine

### PR Process

1. Fork the repository and create a branch from `main`
2. Make your changes — follow existing code patterns and conventions
3. Add or update tests for any changed behavior
4. Run `npm test` (and `npm run test:live` when you touch the agy runner or prompts)
5. Write a clear commit message explaining *why*, not just *what*
6. Open a PR against `main` using the PR template

### Code Conventions

- ESM modules (`.mjs` extension) with `node:` protocol for built-in imports
- No external runtime dependencies — the plugin ships zero `node_modules`
- Functions over classes where possible; the codebase is primarily functional
- No comments unless the *why* is non-obvious
- Keep changes minimal — touch only what's necessary for the fix or feature

### What We Look For in Review

- Does it work? Tests pass, manual verification for runtime changes
- Does it follow existing patterns? Consistency matters more than novelty
- Is it minimal? No unrelated refactoring bundled with the change
- Is it safe? No credential exposure, no unbounded resource usage
